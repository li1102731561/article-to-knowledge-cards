# make-knowledge-cards

把一篇文章拆成 5-8 张知识卡片：每张只讲一个知识点，包含标题、核心知识、简明解释，以及来自原文的例子或一道自测题。

一个纯 Markdown 的 agent skill，适用于 Claude Skills / WorkBuddy Skills 等读取 `SKILL.md` 的 agent，不依赖任何脚本、API 或网络。

---

## 1. 项目解决什么问题

把文章丢给模型「总结一下」，通常得到的是**分段摘要**：按原文顺序复述、重复内容照抄、顺手补上原文没有的背景知识。这种输出有三个毛病：

- **不能复习**。摘要仍依附原文结构，离开原文就看不懂，也没法单独看某一条。
- **真假混杂**。模型会加入自己的常识，读者分不清哪句是作者说的、哪句是模型补的。
- **数量注水**。为了「看起来完整」，一句话会被拆成三条，同一观点换个说法再讲一遍。

这个 skill 换了一种切法：**以「一个可以单独成立的知识点」为单位重组内容，而不是按段落切**。每张卡片是独立的记忆单元，脱离原文也能读懂，可以直接拿去做学习笔记、复习或分享。

它对「信息不够」也有明确行为：原文只够 3 个知识点就输出 3 张并说明原因，不会用常识、背景、评价去凑到 8 张。

## 2. 主要功能

### 输入

| 输入类型 | 支持情况 |
| --- | --- |
| 直接粘贴的文章正文 | 支持，几百字到上万字均可 |
| 本地 `.md` / `.markdown` / `.txt` | 支持，单个或多个 |
| 一个目录（含多篇文本） | 支持，会先列出文件清单让你确认处理哪些 |
| 网页 URL | 不支持，会提示粘贴正文或另存为文本 |
| PDF / Word / EPUB / 图片 / 音视频 | 不支持，会提示转成纯文本 |
| 导出 Anki 牌组、图形界面 | 不支持，只交付 Markdown 卡片 |

不支持的输入不会被硬做，也不会靠文件名猜测内容，而是给出一到两句说明加可执行的替代做法。

### 卡片结构

每张卡片固定 4 个字段，顺序和名称固定：

| 字段 | 规则 |
| --- | --- |
| 标题 | 不超过 18 字，不看正文也知道这张卡讲什么 |
| 核心知识 | 一句话结论，不超过 40 字，单句判断句 |
| 简明解释 | 2-4 句，说明为什么成立、怎么起作用、适用条件 |
| 例子 **或** 自测 | 二选一。原文有具体案例、数据、配置时写「例子」；没有这类材料时换成一道「自测」题 |

第 4 个字段的取舍是硬性的：例子必须来自原文并**提供前三个字段没有的新信息**；把结论换个说法再写一遍不算例子，这种情况改用自测。自测只问一个问题，答案不能从「核心知识」直接抄到。

### 卡片数量

| 原文情况 | 输出 |
| --- | --- |
| 知识点充足 | 5-8 张，通常 6-7 张 |
| 只够 3-4 个独立知识点 | 3-4 张，并在开头加一行说明 |
| 明显超过 8 个知识点 | 取最重要的 8 张，末尾列出被略过的主题 |

### 质量约束

- **不编造**：每条事实、数字、因果、例子都要能在原文定位到。唯一例外是给术语补一句最小必要的释义。
- **一卡一点**：「核心知识」不出现「并且」「同时」连接的两个结论。
- **去重优先**：宁可 5 张互不重复，也不要 8 张里有 3 张讲同一件事。
- **覆盖均衡**：原文每个一级章节至少对应一张卡，砍卡时合并细节而不是整块丢掉一个主题。
- **直接陈述**：卡片里不出现「原文认为」「作者指出」，因为读者可能根本没读过原文。
- **保留限定条件**：原文说「在样本量小于 100 时有效」，卡片不能写成「有效」。

### 输出

- 默认在对话中输出 Markdown 卡片，不写文件。
- 用户要求保存时，写入源文件同目录的 `<源文件名>-cards.md`；粘贴内容则写入 `knowledge-cards.md`。
- 多个文件逐个独立成组，不会把不同主题混在一起。
- 固定输出结构：标题行 → 一行概括（`> 共 N 张卡片｜覆盖：…`）→ 卡片 → `未成卡的内容`。

## 3. 安装方法

无需构建、无需安装依赖，把技能目录放到 agent 读取 skills 的位置即可。

**项目级**（只对当前仓库生效）：

```bash
mkdir -p .workbuddy/skills
cp -r skills/make-knowledge-cards .workbuddy/skills/
```

**用户级**（对所有项目生效）：

```bash
mkdir -p ~/.workbuddy/skills
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

Windows 下用 Git Bash 执行上面的命令，或直接在资源管理器里把 `skills/make-knowledge-cards` 整个目录复制到目标 skills 目录。

安装后目录应为：

```text
<skills 目录>/make-knowledge-cards/
├── SKILL.md
└── agents/
    └── openai.yaml
```

卸载：删除该目录即可，不会留下配置或缓存。

## 4. 使用方法

安装后直接用自然语言描述需求，触发词包括「知识卡片」「做成卡片」「提炼卡片」「学习卡片」「拆成几张卡」，或者给一个 `.md` / `.txt` 路径并说要提炼知识点。

### 粘贴文章

```text
把这篇文章整理成知识卡片：<粘贴正文>
```

### 处理本地文件

```text
把 articles/http-cache.md 做成知识卡片
```

### 一次处理多个文件

```text
把 notes/ 下的复盘.md 和 决策.md 都做成卡片
```

每份文件各自输出一组卡片，用一级标题标明来源文件名，不会合并成一组。

### 保存成文件

```text
把这篇文章做成卡片，存成 md 文件
```

会写到与源文件同目录的 `<源文件名>-cards.md`。没写保存要求时不会产生文件。

### 遇到不支持的输入

```text
帮我把这篇做成卡片：https://example.com/post，还有个 paper.pdf
```

会说明网页不能抓取、PDF 不能解析，并给出替代做法（粘贴正文 / 另存或导出为 `.md`、`.txt`），不会凭链接或文件名编造内容。

## 5. 输入输出示例

**输入**（`http-cache.md` 节选）：

```markdown
## 强缓存：不问服务端就用

第一层叫强缓存。浏览器判断本地副本还在有效期里，就直接用，连请求都不发。
这一层由 Cache-Control: max-age=秒数 控制，从响应生成的那一刻开始倒计时。

强缓存命中时，Network 面板里显示 (from disk cache) 或 (from memory cache)，
状态码是 200 但实际没有网络传输。关键在于：只要还在 max-age 内，
源站的任何改动都不会被感知。

s-maxage 只对共享缓存（CDN、代理）生效，会覆盖 max-age。这意味着可以让
CDN 缓存一小时，而浏览器只缓存五分钟：Cache-Control: max-age=300, s-maxage=3600。
```

**输出**：

```markdown
# 《HTTP 缓存到底是怎么工作的》知识卡片

> 共 6 张卡片｜覆盖：强缓存决定发不发请求、协商缓存决定省不省响应体，两层配合才能既快又能更新。

### 卡片 1｜max-age 内改源站，用户看不到

**核心知识**：max-age 有效期内浏览器直接用本地副本，源站改动不会被感知。

**简明解释**：max-age 是从响应生成那一刻开始倒计时的相对时间，倒计时没走完，浏览器就不去问服务端。于是源站在这个窗口内做的任何改动，用户都拿不到。

**例子**：Network 面板显示 `(from disk cache)` 或 `(from memory cache)`，状态码是 200 却没有网络传输；改了 CSS 用户还看到旧样式，就是这一层的表现。

### 卡片 2｜用 s-maxage 分开两层有效期

**核心知识**：共享缓存的有效期由 `s-maxage` 单独控制。

**简明解释**：共享缓存指 CDN、代理这类服务多方请求的中间层，浏览器私有缓存不读 `s-maxage`，仍按 `max-age` 走。两个值各配一份，就能让边缘节点缓存更久、浏览器缓存更短，在保住命中率的同时加快改动同步。

**例子**：`Cache-Control: max-age=300, s-maxage=3600` 表示 CDN 缓存一小时，浏览器只缓存五分钟。

### 卡片 3｜入口 HTML 不能配长强缓存

…（其余卡片结构相同）

### 卡片 6｜ETag 优先于 Last-Modified
```

注意几点：卡片顺序按重要性排，不跟原文段落顺序；卡片 1 用「例子」而不用「自测」，因为原文有 DevTools 的具体表现可以指认；如果原文只有机制没有案例，这一格会变成一道自测题。

**信息不足时的输出**（约 200 字的短讯），只在开头多一行说明，不凑数量：

```markdown
# 《某开源数据库发布 3.0》知识卡片

> 共 3 张卡片｜覆盖：新增向量索引、许可证改为 SSPL、下月进入 LTS。

> 说明：原文可独立成卡的知识点有限，以下 3 张已覆盖其主要内容。
```

## 目录结构

```text
make-knowledge-cards/
├── SKILL.md            # 技能主体：工作流程、字段规范、质量规则、自检清单、正反示例
└── agents/
    └── openai.yaml     # OpenAI 兼容侧的元数据与调用说明
```

skill 本身不含脚本，全部处理由 agent 按 `SKILL.md` 完成。

## 校验

```bash
python skill-creator/scripts/quick_validate.py skills/make-knowledge-cards
# Skill is valid!
```

`quick_validate.py` 来自 skill-creator 技能包，校验 frontmatter 的 `name` / `description`、命名规范与目录结构。

## 已知取舍

- 数量区间是 5-8 张。信息密度极高的长文会被压到 8 张，被略过的主题在末尾列出；这不是遗漏，是有意的取舍。
- 只输出 Markdown，不生成图片卡片或 Anki 牌组。格式简单，方便自己二次处理。
- 不支持网页抓取，是为了不引入网络依赖和内容不确定性；需要处理网页时先存成文本。
- 卡片是「知识提炼」，不做事实核查：它保证内容来自原文，但不保证原文本身正确。
