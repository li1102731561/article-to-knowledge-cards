# 知识卡片生成

## 概述

把一篇非虚构文章（观点文、方法论、技术说明、课程笔记、行业分析等）拆成 5-8 张独立的知识卡片。每张卡片只承载一个可独立理解的知识点，用于复习、分享或二次整理。

产出的目标不是「文章摘要」，而是「脱离原文也能看懂的独立知识单元」。卡片正文里不出现「原文」「作者」「本文」这类指代，直接陈述知识本身。

## 适用与不适用

适用：

- 用户直接粘贴文章正文（长度从几百字到上万字均可）
- 本地 `.md` / `.markdown` / `.txt` 文件，单个或多个
- 用户提供了文件路径但没说明要做什么，且上下文表明他要提炼知识

不适用（遇到时按「能力边界」处理，不要硬做）：

- 网页 URL、需要抓取的在线内容
- PDF、Word、EPUB、图片、音视频
- 生成 Anki 牌组、`.apkg`，或任何图形界面 / 网页应用

## 能力边界

本 skill 只接受文本，且只输出 Markdown 卡片。

- 收到 URL：说明不能抓取网页，请用户粘贴正文，或先把网页另存为 `.md`/`.txt` 再提供。
- 收到 PDF/Word/图片：说明当前不支持，请用户转成 `.md`/`.txt` 纯文本；不要尝试解析二进制文件。
- 要求 Anki/图形界面：说明不在支持范围内，交付 Markdown 卡片，由用户自行导入。

说明限制时一到两句讲清，紧接着给出可执行的替代做法，不要展开讲原理，也不要反复道歉。混合请求（一篇可处理 + 一篇不可处理）时，先处理能做的，再说明另一篇怎么补。

## 工作流程

### 第 1 步：获取全文

- 粘贴内容：直接使用，忽略「以下是文章」这类包裹语。
- 文件：用 Read 读取。文件超过约 800 行时，先读开头确认结构与主题，再分段读完全文，不要只读前几屏就动笔。
- 多个文件：逐个文件独立处理，每份文件各自输出一组卡片，用一级标题标明来源文件名。不要把多篇不同主题的文章混成一组卡片。
- 目录或大量文件：先列出文件清单让用户确认要处理哪些，避免一次性产出几十组卡片。

读完后先在心里（不要输出）回答三个问题：这篇文章的主线论点是什么？它讲了哪几种互相独立的东西？哪些段落只是重复、铺垫或情绪表达？

### 第 2 步：抽取候选知识点

以「一个可以单独成立的主张、机制、方法、区分或事实」为单位切分，而不是按段落切分。

合格的候选点通常长这样：

- 一个因果关系：因为 X，所以 Y
- 一个机制：某事物通过哪几步起作用
- 一个方法步骤：做某事的正确顺序或关键动作
- 一个区分：A 和 B 的本质差别，以及为什么这个差别重要
- 一个反直觉结论：多数人以为……实际上……
- 一个可验证的事实或数据：具体数字、时间、比例

不合格的候选点：时代背景介绍、作者的个人经历铺垫、情绪化评论、纯过渡句、「综上所述」。

### 第 3 步：筛选、去重与排序

按下面的优先级保留，直到数量落进区间：

1. 支撑全文主线的核心论点（必留，通常 1-2 张）
2. 可迁移的方法、机制、判断标准（价值最高）
3. 关键区分与常见误区
4. 有信息量的具体事实、数据、案例

然后去重：

- 同一知识点的两次表述（前言提一次、结尾再提一次）合并成一张卡片。
- 上位概念与其例子不拆成两张卡；例子写进卡片的「例子」字段。
- 一个方法有 5 个步骤时，如果步骤共同服务于同一个目的，合并成一张「流程卡」，把步骤列在解释里；只有当某一步本身可以独立成论时才单独成卡。
- 检查层级重叠：如果一张卡讲「A 与 B 的分工」，另一张卡单独展开其中一半，两张会大幅重复。保留信息更具体的那张，或把两张合并成一张。

最后排序：按重要性从高到低排，把主线结论和可迁移的方法放前面。不要沿用原文的行文顺序，也不要让「背景」类内容占据第 1 张。

同时检查覆盖均衡：原文每个一级章节至少对应一张卡（该章节本身没有独立知识点时除外）。数量超限需要砍卡时，优先合并同一主题内的细节，不要整块丢掉一个独立主题。

### 第 4 步：定卡片数量

- 目标区间 5-8 张。原文信息量足够时，取 6-7 张通常最稳。
- 原文只够 3-4 个独立知识点时，就输出 3-4 张，并加一行说明（格式见第 6 步）。不要为了凑数把一句话拆成三张，也不要换个说法重复同一观点。
- 发布、上线、活动安排这类孤立的事务性信息成卡价值低。优先并入相关卡片，或放进「未成卡的内容」，不要为它单独占一张卡。
- 原文知识点明显超过 8 个时，按第 3 步的优先级取最重要的 8 个，其余在末尾一行列出被略过的主题（只列主题名，不展开）。

### 第 5 步：撰写卡片

每张卡片固定 **4 个字段**：标题、核心知识、简明解释，以及第 4 个字段——「例子」或「自测」二选一。不要两个都写，也不要两个都不写，不要增删或改名。

```markdown
### 卡片 N｜标题（不超过 18 字，能不看正文就知道这张卡讲什么）

**核心知识**：一句话结论，不超过 40 字，必须是完整的判断句。

**简明解释**：2-4 句，说明它为什么成立、怎么起作用、适用条件是什么。保留必要术语，其余用读者能懂的话。

**例子**：原文中的具体案例、数据、配置或场景对照，1-2 句。
```

第 4 个字段的判定顺序：

1. 原文里有具体案例、实测数据、代码/配置、真实场景或明确对照 → 用 `**例子**`。
2. 没有上述材料 → 用 `**自测**：一个问题，替换掉「例子」这一行。`
3. 有这类材料，但已经完整写进「核心知识」和「简明解释」→ 还是用 `**自测**`。同一个材料在两处出现，第二次就没有信息量了。

「例子」的硬性标准：必须是原文中可以直接指认的具体材料，并且提供「核心知识」和「简明解释」里没有的新信息。以下都不算例子，遇到就用「自测」代替：

- 把原文的结论、定义或建议换个说法再写一遍
- 复述方法步骤或流程本身
- 以「原文认为」「原文给出的做法是」「作者举例说」开头（卡片里本来就不该出现这类转述）
- 自己补的类比、联想、生活场景

「自测」的硬性标准：

- 只提一个问题。不要出现「……？这一步由哪一层接管？」这类连续追问。
- 答案不能直接从「核心知识」那一行抄到，必须是需要回忆解释里的条件、区别、后果或边界才能回答。
- 优先问「为什么」「什么条件下不成立」「两者的差别在哪」「换个情形会怎样」，不要问「是什么」「有哪几点」。
- 可以构造假设情形来考应用（例如「如果只做了 A 没做 B，会怎样」），但情形只能用原文已有的要素重组，不能引入原文没有的事实、数据、案例或人物。

写完后逐张对照文末的「自检清单」，通过后再输出。

### 第 6 步：输出

默认在对话中直接输出完整卡片，不写文件。用户明确要求保存时，写入与源文件同目录的 `<源文件名>-cards.md`；粘贴内容则写入 `knowledge-cards.md`。

输出结构（严格照此排版）：

```markdown
# 《文章标题》知识卡片

> 共 N 张卡片｜覆盖：一句话概括全文主线（不超过 50 字）

### 卡片 1｜……
...

### 卡片 N｜……
...

---
**未成卡的内容**：被略过但用户可能关心的次要主题（没有就整段省略）
```

数量不足 5 张时，在「> 共 N 张卡片」这一行下面紧跟一行，格式固定：

```markdown
> 共 3 张卡片｜覆盖：……

> 说明：原文可独立成卡的知识点有限，以下 3 张已覆盖其主要内容。
```

标题行：用户提供了标题或文件名就用它；都没有时依据主线自拟一个不超过 15 字的标题，不要写「未命名文章」。

保存为文件时，文件内容只包含上述结构，不要加「以下是生成结果」之类的开场语。中文正文使用中文标点，引号统一用「」或“”，不要混入英文直引号。

## 示例

合格卡片：

```markdown
### 卡片 4｜用 s-maxage 分开两层有效期

**核心知识**：共享缓存的有效期由 `s-maxage` 单独控制。

**简明解释**：共享缓存指 CDN、代理这类服务多方请求的中间层，浏览器私有缓存不读 `s-maxage`，仍按 `max-age` 走。两个值各配一份，就能让边缘节点缓存更久、浏览器缓存更短，在保住命中率的同时加快改动同步。

**例子**：`Cache-Control: max-age=300, s-maxage=3600` 表示 CDN 缓存一小时，浏览器只缓存五分钟。
```

不合格卡片与原因：

```markdown
### 卡片 4｜缓存配置

**核心知识**：CDN 缓存和浏览器缓存的有效期可以分开设置，并且要注意 s-maxage 只对共享缓存生效。

**简明解释**：原文作者指出，我们可以通过配置来优化缓存策略。这对性能优化很有帮助，值得大家重视。

**例子**：原文给出的做法是把两个值分开配置。
```

问题：标题是话题词不是结论；核心知识超过 40 字且用「并且」塞了两个结论；解释里出现「原文作者指出」「值得大家重视」的空话且没说明机制；例子只是复述结论，没有任何新信息。

## 硬性质量规则

以下规则优先级高于「卡片好看」和「数量达标」：

1. **不编造**。卡片中的每个事实、数字、因果、例子都必须能在原文找到依据。原文没说的背景知识、延伸推论、行业常识一律不写。原文表述模糊时，按原文的模糊程度写，不要替作者补全。
   唯一例外是术语释义：遇到缩写或专业名词，可以补一句最小必要的通用释义（全称、通用含义）帮助读者读懂。但不得由释义推出影响、结论或评价，也不得补充数据。不确定释义是否准确时，宁可原样保留术语不加解释。
2. **一卡一点**。「核心知识」必须是单句，不出现「并且」「同时」「另外」连接的两个独立结论——有就拆开或砍掉次要的那个。
3. **直接陈述**。卡片正文不出现「原文」「作者」「本文」「文章中提到」。要知道卡片是给「没读过原文的人」看的，转述句会让卡片失去独立性。
4. **去重优先于凑数**。宁可 5 张互不重复，也不要 8 张里有 3 张在讲同一件事。
5. **信息不足就说不足**。原文只有 2-3 个知识点时，输出 2-3 张并说明原因，不要用常识、背景、评价来填充。
6. **保留原文的限定条件**。原文说「在样本量小于 100 时有效」，卡片就不能写成「有效」；原文说「官方数据」，卡片不能写成「业界公认」。
7. **标题要具体**。「第三部分」「关于方法」「总结」「缓存」这类标题直接重写；标题应让人不看正文就知道这张卡讲什么。
8. **术语与数字照抄原文**。不要同义替换专有名词，不要四舍五入关键数据。

## 自检清单

交付前逐条核对，任何一条不通过就改：

- [ ] 卡片数量在 5-8 之间，或已按第 4 步说明为何少于 5
- [ ] 每张卡片只有 4 个字段，第 4 个字段是「例子」或「自测」之一，没有两个都写
- [ ] 每张卡片只有一个知识点，「核心知识」是单句判断句且不超过 40 字
- [ ] 「简明解释」说明了机制或原因，没有「很重要」「值得重视」这类空话
- [ ] 「例子」提供了解释里没有的新信息；不是结论复述，不是自造的类比
- [ ] 「自测」只问一个问题，答案不能从「核心知识」直接抄到
- [ ] 卡片正文没有出现「原文」「作者」「本文」
- [ ] 没有两张卡片在讲同一件事
- [ ] 每张卡片的事实都能在原文定位到，没有加入原文之外的信息
- [ ] 标题具体，没有「引言/背景/总结」这类空标题
- [ ] 卡片顺序按重要性排列，不是原文行文顺序
- [ ] 原文每个一级章节都有对应卡片，被砍掉的主题已列入「未成卡的内容」

## 常见错误

| 错误做法 | 问题 | 正确做法 |
| --- | --- | --- |
| 按文章段落一张一张切 | 得到的是分段摘要，不是知识卡 | 按「独立知识点」重组，跨段落合并 |
| 每张卡片都写「作者认为……」 | 卡片变成转述，无法独立使用 | 直接陈述知识本身 |
| 例子写成结论的复述 | 字段冗余，读者读不到新信息 | 换用「自测」问题 |
| 为了 8 张把一句话拆成三张 | 卡片之间高度重叠 | 合并，数量降到 5-6 张 |
| 补一个「现实中的应用」段落 | 引入原文没有的信息 | 只写在原文有依据的内容 |
| 把全文总结做成第 8 张卡 | 与其他卡片重复 | 总结放在开头的一行概括里 |
| 自测写成连续追问 | 不是「一个问题」，且暴露思路 | 只留最能检验理解的那一问 |
